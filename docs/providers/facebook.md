# Facebook Pages

| | |
| --- | --- |
| Provider id | `facebook` |
| OAuth family | `meta` (shared with [Instagram](./instagram.md)) |
| API | Meta Graph API `v26.0` |
| Manifest | `shared/src/providers/manifests/facebook.ts` |
| Implementation | `functions/src/providers/facebook/facebookProvider.ts` |
| Status | **IMPLEMENTED — APP REVIEW NEEDED** |

Publishing targets a **Facebook Page**, never a personal profile. Meta has no
public API for posting to a personal timeline, and CrepeLite does not attempt
to work around that.

## OAuth

Server-side confidential client. `state` plus a server-side nonce protects the
callback; PKCE is not used because the client secret never leaves the backend.

Redirect URI to register in the Meta app:

```
https://<your-domain>/api/oauth/callback
```

This is **one shared redirect URI for every provider** — the backend
identifies the provider from the signed `state` parameter, not from the path.
It can be overridden with the `OAUTH_REDIRECT_URI` environment variable.


### Scopes requested

| Scope | Why |
| --- | --- |
| `pages_show_list` | List the Pages the user administers |
| `pages_read_engagement` | Read Page metadata and published posts |
| `pages_manage_posts` | Create, edit and delete Page posts |
| `business_management` | Resolve Pages owned through a Business portfolio |
| `instagram_basic` | Discover the Instagram account linked to a Page |
| `instagram_content_publish` | Publish to that Instagram account |

The last two belong to Instagram but are part of the same grant — one
authorisation connects both networks.

## Account requirements

- A Facebook Page (not a profile).
- The connecting user must have a Page role that includes `CREATE_CONTENT`.
- Pages owned by a Business portfolio need `business_management` to enumerate.

## Supported publication types

| Type | Supported | Notes |
| --- | --- | --- |
| Text only | Yes | Link preview is generated by Facebook |
| Single image | Yes | |
| Multi-image | Yes | Published as a multi-photo post |
| Video | Yes | Resumable upload, asynchronous processing |
| Reels | Yes | Vertical video; separate publishing endpoint |
| Stories | No | Not exposed for Pages through the public API |

## After publishing

`canEditPublishedPost` is **true**: the post message can be edited through the
Graph API. Deletion is supported. CrepeLite never deletes-and-reposts as a
substitute for editing.

## Rate limits

- Concurrency in CrepeLite: **2** publishes per channel.
- Meta returns usage headers; the client backs off on them (`strategy: headers`).
- Documented publish quota: **Reels — 30 API-published per Page per 24 hours**.

## App Review requirements

These are the manual steps only the app owner can perform. See also
[`../provider-approval-checklist.md`](../provider-approval-checklist.md).

1. Create an app at [developers.facebook.com](https://developers.facebook.com)
   of type **Business**.
2. Add the **Facebook Login** and **Instagram** products.
3. Register the redirect URI above under Facebook Login → Settings.
4. Complete **Business Verification** for the owning Business portfolio.
5. Submit each of the scopes above for **App Review**, with a screencast showing
   the connect-and-publish flow.
6. Until review passes, only users with a role on the app (admin, developer,
   tester) can connect. This is enough to test the whole flow end to end.

## Known limitations

- No personal-profile publishing.
- No Stories for Pages.
- Video processing is asynchronous: a delivery can sit in `processing` for
  several minutes before it becomes `published`. CrepeLite polls for the final
  state rather than assuming success.
